# OrgShield AI - Dataset Documentation & Inventory

## 1. Normal Communication Dataset: Enron Email Corpus

### 1.1 Dataset Provenance & Structure
The Enron Email Dataset was collected and prepared by the CALO Project (Cognitive Assistant that Learns and Organizes) and released publicly by the Federal Energy Regulatory Commission (FERC) during its investigation into Enron Corporation.

In the project root:
- Primary directory: `enron_mail_20150507_final/maildir`
- Secondary / subset directory: `enron_mail_20150507/maildir`
- Directory format: Standard `maildir` structure containing 150 employees (e.g., `allen-p`, `arnold-j`, `skilling-j`, `lay-k`).
- Email formatting: RFC 2822 / MIME format generated by JavaMail, containing standard headers (`Message-ID`, `Date`, `From`, `To`, `Subject`, `Mime-Version`, `Content-Type`, `X-From`, `X-To`, `X-Origin`, `X-Folder`, and plain-text message bodies).

### 1.2 Ingestion & Sampling Protocol
- **Streaming Pipeline**: The dataset is streamed user-by-user using Python's standard `email` library with `policy.default`. No files are bulk-loaded into RAM simultaneously, strictly abiding by memory and resource boundaries.
- **Representative Sampling**: In the default pipeline, 6,000 emails are sampled evenly across all 150 employees (~40–50 emails per user) to capture the broad organizational variance across trading, executive, research, and legal functions.

### 1.3 Dataset Inventory & Statistics (Generated from Exploration)
The dataset exploration engine (`ml/preprocessing/dataset_explorer.py`) generates empirical statistics stored in `reports/dataset/dataset_inventory.json`:

- **Total Employees Represented**: 121–150 employees
- **Unique Senders**: 1,609
- **Unique Recipients**: 8,325
- **Unique Sender Domains**: 234 domains (primary: `enron.com`)
- **Missing Field Statistics**:

  - Missing Subject: 83

- **URL Statistics**:
  - Emails containing hyperlinks: 624 (10.4%)
  - Total hyperlinks extracted: 1,482
  - Emails containing IP-addressed URLs: 8

### 1.4 Historical Corpus Contamination
The Enron corpus is a real-world enterprise dataset from 1998–2002. As such, it contains unsolicited marketing, sweepstakes, and early phishing/spam solicitations received by employees (e.g. `prizemachine@feedback.iwon.com`, casino advertisements, wire transfer solicitations).
The exploration module flags these samples under `reports/dataset/dataset_inventory.json` ("corpus_contamination_notes") to provide awareness that real organizational inboxes have baseline noise.

### 1.5 Leakage-Aware Thread Partitioning
To prevent email thread leakage between training, validation, and test sets, partitioning is performed using **thread-grouped splitting**:
- Normal subjects (with `Re:`, `Fwd:`, `FW:` stripped) are clustered into conversation threads.
- Entire threads are assigned atomically to either Training (70%), Validation (15%), or Test (15%).
- Resulting Split:
  - **Training Set (Normal only)**: 4,200 emails
  - **Validation Set (Normal only)**: 1,041 emails
  - **Held-Out Test Set (Normal only)**: 759 emails

## 2. Held-Out Phishing Benchmark Dataset

### 2.1 Provenance & Purpose
Because unsupervised learning requires learning exclusively from normal communication, phishing examples are reserved strictly for held-out evaluation.
We compiled a curated benchmark of 100 documented phishing attacks located at `ml/data/phishing_benchmark.json`.

### 2.2 Attack Archetypes Represented
The benchmark includes 10 threat categories modeled after public cybersecurity archives:
1. **Credential Harvesting (Microsoft 365 / O365)**: Fake password expiration notices directing to IP login portals.
2. **Banking & Financial Account Suspension**: Wells Fargo / Chase alerts notifying users of unauthorized access.
3. **Business Email Compromise (BEC / CEO Fraud)**: Urgent executive wire transfer requests spoofing senior officers (e.g. Ken Lay).
4. **IT Helpdesk & VPN Upgrades**: Mandatory SSL VPN certificate updates requiring Active Directory re-authentication.
5. **E-Commerce & Payment Fraud**: PayPal fraudulent receipt confirmations with cancellation phishing links.
6. **Logistics & Package Delivery Scams**: DHL / FedEx customs clearance fee demands.
7. **Human Resources & Payroll Discrepancies**: Year-end bonus and health insurance re-enrollment deadlines.
8. **Direct IP Login Traps**: Communications using raw IPv4 hosts in URLs rather than domain names.
9. **Reply-To Redirection Attacks**: Legitimate-looking sender address paired with an external attacker collection domain.
10. **Advance Fee / Lottery Lures**: High-payout lottery sweepstakes requiring immediate banking disclosure.

### 2.3 How to Add Additional Phishing Benchmarks
To evaluate against a new external dataset (e.g., full Jose Nazario Phishing Corpus, Kaggle Phishing datasets, or private incident response feeds):
1. Format emails into JSON records with keys: `id`, `sender`, `recipients`, `subject`, `body`, `reply_to`, `date`.
2. Save file as `ml/data/<your_phishing_dataset>.json`.
3. In `ml/training/train_and_evaluate.py`, point `phish_path` to your file and execute:
   ```bash
   python scripts/train_models.py
   ```
4. All metrics (Precision, Recall, Detection Rate, False Positives per 1,000, PR-AUC) will recompute and export to `reports/evaluation/model_comparison.json`.
